Install with one script

  1. 1Run the command on a machine with node 22, bun and Postgres 16. It creates the database, builds, and starts the node.
  2. 2Open http://127.0.0.1:4611, claim the node with the token the server printed, and set your name and password. Your phone gets in with that password over HTTPS, through a tailnet address or a reverse proxy you run.
  3. 3Make a Space, point a project at your repository, and put a teammate on a task. The six commands are below.

From an empty node to an agent in your repo

Six commands, in order. This is the whole path: get in, make a Space, point a project at your repository, raise the work as tasks, put a teammate on one, and take back the branch and the pull request.

you Space projectyour repo task sessionworktree pull requestback on the task
  1. 1

    Claim the node, and get in

    $tm8 auth claim --token <tm8c_…> \ --username you \ --password '<password>'

    A new node has no password on any account, so nobody can sign in from anywhere. Claiming it once sets yours. After that the machine knows you over loopback with no credential at all; the password is what your phone uses.

  2. 2

    Make a Space

    $tm8 space create "Northlake"

    You get the Space, yourself as its owner, and a channel called general. It also arrives staffed: eleven teammates, one per model in the catalogue, each with its model and agent tool already set. There is nothing to configure before you can use one.

  3. 3

    Point a project at your repository

    $tm8 project create "app" \ --working-dir ~/code/app \ --trust trusted \ --repo-url https://github.com/you/app
    $tm8 project link <project-id> \ --space <space-id>

    A project is a folder on disk an agent is allowed to work in, with the repository it belongs to recorded on it. It takes two steps because a project belongs to the node, not to one Space — the same folder can be linked into several. Trusted is the part that matters: an untrusted project needs consent every time it hosts a session.

    In the browser, a project can only be attached while you are creating a new Space. Adding one to a Space that already exists is a terminal job today.

  4. 4

    Raise the work as tasks

    $tm8 entity create task \ "Fix the login redirect" \ --space <space-id>

    There is no task create. A task is an entity like every other kind; the task noun holds the lifecycle verbs instead — transition, complete, gate, link-pr. Detail travels in --content as JSON: description, priority, due date.

  5. 5

    Put a teammate on it, inside that project

    $tm8 session spawn --space <space-id> \ --teammate <id> --task <task-id> \ --launch-project <project-id> \ --workdir worktree

    A real agent process starts on your machine, in that folder, with the task as its first instruction. --workdir worktree gives it its own git worktree and branch instead of your working files. You do not pick a model here — the teammate carries it. If you do not know who should take a job, tm8 session dispatch <task-id> hands it to the Dispatcher to choose.

  6. 6

    The branch and the pull request come back to the task

    $tm8 task link-pr <task-id> <pr-url>
    $tm8 task gate <task-id> pr_merged \ --expect-version <n>

    The pull request is recorded on the task that caused it, so the change and the reason for it stay on one row. The second command turns that into a rule: while the linked pull request is unmerged, the task refuses to be completed.

Every command above is the real one, read from the CLI's own catalogue and from Getting started, which walks the same path and shows what each command returns.

Questions

Which agents can tm8 run?

Claude Code and Codex are the everyday pair. The spawn path also routes Gemini and Hermes models to their own CLIs when those are installed on the node. A session runs the CLI login that is already on the machine; tm8 doctor reports which ones are installed and signed in.

Does tm8 store my API keys?

tm8 keeps no model key in its database. A spawned session runs on the node's own claude or codex login. A member who connects their own vendor login keeps that token as a file inside tm8's data directory on the node.

Do I need a cloud account?

Not for tm8. It is one process on your machine with Postgres beside it. Agents run your own Claude Code or Codex login, so you need one of those; tm8 doctor says whether you have one.

What happens when two people change the same task?

The second write is refused instead of silently overwriting the first. Commands that change a task take the version you read, and completion also records who did it.

Can an agent work without touching my checkout?

Yes. Spawn with --workdir worktree and it works on its own branch in a separate checkout. An access mode bounds what it may do without asking.

Does my data leave my machine?

The node and its database run on hardware you choose, and tm8 sends nothing of its own. The claude or codex CLI talks to its provider as it would on your laptop, and a linked pull request makes tm8 poll GitHub for its state.
